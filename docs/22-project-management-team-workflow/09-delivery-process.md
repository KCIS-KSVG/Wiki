
归档文件夹应包含一个 README 文件，记录项目的基本信息（如项目名称、日期、关键人员、文件结构说明），便于未来快速检索。

### 归档存储位置

**建议方案**：原始素材和项目文件存放至 NAS 或归档级 HDD（两份副本：工作盘+备份盘）。交付作品保留在云存储中，便于快速访问。项目文档保存在团队共享文档库中。

## 五、项目质量复盘

在项目交付和归档完成后，建议进行项目质量复盘。复盘的核心是总结经验、优化流程。

### 复盘内容

质量复盘应覆盖四个方面的内容：前期规划是否充分、现场执行是否顺畅、后期处理效率如何、团队协作是否存在改进空间。围绕这些问题收集反馈，记录可在未来项目中优化的流程和可复用的成功经验。

### 复盘形式

小型项目：通过简短团队内部沟通完成快速复盘。中大型项目：召开正式项目复盘会议，各环节负责人参与，形成书面复盘记录。

### 复盘产出

每次项目复盘应形成可沉淀的成果：更新项目模板、修订设备清单、完善 SOP、补充最佳实践案例库。这些产出物是团队知识库持续演进的核心素材。缺乏复盘产出的回顾，仅停留在经验交流层面，难以转化为组织能力的实质提升。

## 六、常见误区与避坑指南

::: warning ⚠️ 避坑指南

**误区一：作品导出后就可以直接交付，不需要最终审核。**

导出过程中可能出现色彩空间转换错误、文件名错误或压缩问题。交付前应在播放环境中完整审查一遍，确认无误后再发送给客户。

**误区二：客户确认后就不需要保留项目文件了。**

项目文件是未来修改和复用的基础。即使客户已确认交付，建议保留项目文件和原始素材至少一年（或根据合同约定），以应对可能的后续需求。

**误区三：归档就是把所有文件堆到一个文件夹里。**

归档的目的是便于未来检索和使用。应按照统一规范整理文件夹结构，并附带 README 说明文件。混乱的归档在需要使用时形同虚设。

**误区四：质量复盘是可有可无的环节。**

复盘是将项目经验转化为团队能力的关键步骤。忽视复盘，意味着同样的错误可能在未来的项目中重复发生，团队能力的提升也会因此停滞。
:::

## 总结

作品审核发布与归档是摄影项目的收尾阶段，也是保障客户满意和团队经验沉淀的关键环节。交付前应完成最终审核，确认数量、格式、色彩和命名的规范性。交付方式应根据项目类型和客户需求灵活选择，反馈收集应引导客户提供可操作的修改意见。项目归档应包含原始素材、项目文件、交付作品和项目文档四大类，按统一的文件夹结构存放。质量复盘是将项目经验转化为团队长期能力的关键机制，不应被忽视。
